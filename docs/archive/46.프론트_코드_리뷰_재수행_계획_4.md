# 프론트 코드 리뷰 재수행 계획 4

## 배경/문제
- 37번 계획에 따라 리뷰가 진행되었으나, 38~44번 문서는 해당 결과를 기반으로 작성되었음
- 추가로 점검해야 할 항목이 남아있는지 확인하기 위해, 동일한 기준으로 독립적인 재검토가 필요함
- 이전 문서를 참조하지 않고 37번 계획만 기준으로 재실행하여 누락 가능성을 줄이고자 함

## 목표
- 37번 계획의 단계별 리뷰를 처음부터 다시 수행한다
- 기존 결과와 무관하게, 구조/품질/성능/테스트 관점의 이슈를 새로 식별한다
- 추가 검토 항목 여부와 후속 정리 필요성을 명확히 제시한다

## 범위
- 포함: `frontend` 디렉토리 전반(구조, 상태 관리, 컴포넌트, API 연동, 성능, 테스트)
- 제외: 백엔드/인프라/데이터 파이프라인 상세 코드 리뷰
- 제한: 38~44번 문서 내용은 참조하지 않는다

## 현재 동작 정리
- 37번 계획서에 명시된 대상 파일/폴더를 동일하게 적용한다
- 단계별로 확인 포인트에 맞춰 정리하며, 관찰 결과는 새 기준으로 기록한다
- 이전 결과와 비교는 최종 요약 단계에서만 수행한다

## 개선 방향
- 객관성 유지: 기존 결론을 배제하고 관찰 사실 중심으로 기록
- 단계별 일관성: 37번의 Step 정의와 완료 기준을 유지
- 누락 최소화: 설정 → 라우팅 → 컴포넌트 → 상태 → 데이터 → UI/국제화 순서 준수

## 단계별 계획
- Step 0: 리뷰 범위 고정 및 기본 문서 확인
  - 대상 파일/폴더: `frontend/README.md`, `frontend/package.json`, `frontend/vite.config.ts`, `frontend/tsconfig*.json`, `frontend/eslint.config.js`, `frontend/tailwind.config.cjs`, `frontend/postcss.config.cjs`
  - 확인 포인트: 빌드/테스트 스크립트, 린트 규칙, 타입스크립트 경계
  - 완료 기준: 리뷰 범위/규칙/빌드 전제 정리
- Step 1: 엔트리포인트/라우팅/전역 스타일 흐름 정리
  - 대상 파일/폴더: `frontend/src/main.tsx`, `frontend/src/App.tsx`, `frontend/src/router.tsx`, `frontend/src/routes/*.tsx`, `frontend/src/index.css`, `frontend/src/assets/**`
  - 확인 포인트: 라우트 구조, 레이아웃 책임 분리, 전역 스타일 영향 범위
  - 완료 기준: 화면 진입 경로/라우트 맵 정리
- Step 2: 핵심 화면/컴포넌트 구조 점검
  - 대상 파일/폴더: `frontend/src/components/home/**`, `frontend/src/components/CategoryInlineCreator.tsx`, `frontend/src/components/common/**`
  - 확인 포인트: 컴포넌트 책임/props 경계, 재사용성, 과도한 상태 결합 여부
  - 완료 기준: 복잡도 높은 화면/컴포넌트 목록과 이유 기록
- Step 3: 훅/상태 전파 경로 점검
  - 대상 파일/폴더: `frontend/src/hooks/*.ts`, `frontend/src/hooks/*.tsx`, `frontend/src/store/settingsStore.ts`
  - 확인 포인트: 상태 소유권/결합, 사이드이펙트 위치, 훅 간 의존성
  - 완료 기준: 상태 관리 리팩토링 후보 정리
- Step 4: 데이터 계층 및 API 유틸 점검
  - 대상 파일/폴더: `frontend/src/lib/api.ts`, `frontend/src/lib/api/generated.ts`, `frontend/src/lib/queryKeys.ts`, `frontend/src/lib/threadCache.ts`, `frontend/src/lib/useDebouncedValue.ts`, `frontend/src/lib/entryOrder.ts`, `frontend/src/lib/entryDepth.ts`
  - 확인 포인트: 캐시/쿼리 키 관리, 에러 처리 일관성, API 호출 책임 분리
  - 완료 기준: 데이터 계층 개선 포인트 정리
- Step 5: UI 토큰/유틸/국제화 점검
  - 대상 파일/폴더: `frontend/src/lib/uiTheme.ts`, `frontend/src/lib/uiTokens.ts`, `frontend/src/lib/mutedText.ts`, `frontend/src/lib/highlightMatches.tsx`, `frontend/src/i18n.ts`, `frontend/src/locales/**`, `frontend/src/lib/languages.ts`
  - 확인 포인트: 테마/타이포/컬러 일관성, 텍스트 처리, 번역 키 관리
  - 완료 기준: UI 유틸/국제화 리스크 정리
- Step 6: 결과 정리 및 추가 검토 항목 도출
  - 변경 내용: 이슈 목록을 심각도/난이도/효익 기준으로 분류
  - 완료 기준: 추가 검토 필요 영역과 후속 정리 필요성 명시
