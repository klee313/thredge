# 프론트 코드 리뷰 재수행 계획

## 배경/문제
- 37번 계획에 따라 진행한 리뷰 이후 추가 검토 항목이 남았는지 재확인이 필요함
- 이전 리뷰 결과에 의존하지 않고 동일한 절차로 다시 점검해 누락을 방지해야 함

## 목표
- 37번 계획의 단계별 절차를 처음부터 다시 수행한다
- 추가 개선/리스크 항목이 존재하는지 독립적으로 확인한다
- 우선순위 제안 목록을 최신 상태로 정리한다

## 범위
- 포함: `frontend` 디렉토리 전반(구조, 상태 관리, 컴포넌트, API 연동, 성능, 테스트)
- 제외: 백엔드/인프라/데이터 파이프라인 상세 코드 리뷰

## 현재 동작 정리
- 37번 계획의 Step 0~6을 동일한 순서로 재수행한다
- 이전 리뷰 기록을 참고하지 않고, 현재 코드 기준으로 흐름을 재구성한다
- 단계별 산출물(이슈 목록/완료 기준)을 다시 작성한다

## 개선 방향
- 유지보수성: 책임 분리, 의존성 감소, 재사용성 향상
- 안정성: 런타임 오류 가능 지점 축소, 경계 조건 정비
- 성능: 렌더링/네트워크 병목 지점 파악
- 테스트성: 단위/통합 테스트 추가 여지 확인

  - 완료 기준: 리뷰 범위/규칙/빌드 전제 재정리

## 단계별 재점검 결과(발견 사항)
- Step 0
  - 특이사항 없음 (빌드/린트/TS 설정 구조는 일관됨)
  - 확인 필요: `frontend` 루트에서 린트/타입체크 실행 전제(루트 실행 시 경로/프로젝트 해석 확인 필요)
- Step 1
  - `frontend/src/main.tsx`: 전역 Query/Mutation 에러가 콘솔 로그로만 처리됨 → 사용자 가시 오류 채널 부재(UX/운영 관점 개선 후보)
  - `frontend/src/routes/SettingsPage.tsx`: 비밀번호 변경 검증 메시지가 영어 하드코딩 → i18n 일관성 저하(현지화 개선 후보)
- Step 2
  - `frontend/src/components/home/ThreadEditor.tsx`: `useEffect` 사용하지만 import 누락 → 빌드/린트 에러 확정
  - `frontend/src/components/home/CategoryFilterBar.tsx`: 검색 포커스 해제 시 목록이 축소되어 확장 목록에서 클릭이 누락될 수 있음(UX 리스크)
- Step 3
  - `frontend/src/hooks/useThreadDetailState.ts`: `syncThread`로 편집값을 항상 채우고 `hasDrafts`가 이를 draft로 간주 → **편집하지 않아도** 로컬스토리지에 스레드 본문이 계속 저장됨(스토리지 팽창/불필요한 데이터 보관)
  - `frontend/src/hooks/useHomeFeedState.ts`: 로컬스토리지 키가 사용자 구분 없이 고정 → 다계정/공용 브라우저 환경에서 초안/편집 내용이 섞일 수 있음(프라이버시/UX 리스크)
- Step 4
  - `frontend/src/components/home/HomeFeed.tsx` → `frontend/src/lib/api.ts`: `categoryIds`에 `UNCATEGORIZED_TOKEN` 문자열을 함께 전송 → 백엔드가 UUID만 기대하면 필터 동작 불안정(계약 확인 필요)
- Step 5
  - `frontend/src/lib/highlightMatches.tsx`: 사용자 입력 텍스트가 HTML/URL로 변환되어 `dangerouslySetInnerHTML`에 전달됨 → 서버 측 sanitization 부재 시 XSS 위험
  - `frontend/src/lib/highlightMatches.tsx`: URL을 HTML 속성에 직접 주입(escape 없음) → 속성 주입/스크립트 삽입 가능성
