# 프론트 리뷰 후속 개선 계획

## 배경/문제
- Step 0~5 리뷰 결과가 분산되어 있어 실제 리팩토링을 단계별로 진행하기 어렵다.
- 화면/훅/데이터/테마/국제화에서 리스크가 발견되었으나 우선순위와 범위가 명확히 정리되지 않았다.

## 목표
- Step 0~5에서 발견된 개선 포인트를 하나의 실행 계획으로 통합한다.
- 리팩토링 단계를 순서화하고 각 단계의 완료 기준을 명시한다.
- 진행 시점마다 변경 범위를 추적할 수 있도록 체크리스트를 제공한다.

## 범위
- 포함: 프론트엔드 구조/상태/데이터 계층/공통 UI/국제화 개선
- 제외: 백엔드 변경, 인프라/배포 파이프라인 변경, 디자인 전면 개편

## 현재 동작 정리
- Step 0~5 리뷰 결과를 기준으로 구조적 위험/중복/결합 지점을 재정리한다.
- 전역 상태/로컬 저장/라우팅/데이터 캐시/테마/i18n에 대한 개선 후보가 존재한다.

## 개선 방향
- 책임 분리: 화면/훅/데이터 계층의 역할 분리
- 안정성: 에러 처리/상태 동기화 일관성 강화
- 성능: 캐시 무효화 최소화, 렌더링 부담 축소
- 접근성/국제화: 공통 컴포넌트의 a11y 및 i18n 적용 확대

## 단계별 계획
- Step 1: 우선순위 확정 및 리팩토링 범위 고정
  - 변경 내용: Step 0~5 이슈를 심각도/난이도/효익 기준으로 분류하고, 이번 사이클에서 다룰 범위를 확정
  - 완료 기준: 우선순위 매트릭스와 범위 확정 목록 작성
- Step 2: 구조/화면 책임 분리
  - 변경 내용: `HomeFeed`, `ThreadCard`, `ThreadDetailPage`의 중복 로직 추출 및 컨테이너/프레젠테이션 분리
  - 완료 기준: 화면별 핵심 책임이 문서화되고 중복 로직이 공통 유틸/컴포넌트로 이동
- Step 3: 훅/상태 동기화 정리
  - 변경 내용: `useHomeFeedState` 저장/URL 동기화 분리, `useThreadDetailState` 복원 규칙 정리, `useThreadUiState` 동기화 경계 정립
  - 완료 기준: 상태 저장/복원 규칙이 단일화되고 테스트 가능한 규칙으로 정리
- Step 4: 데이터 계층 및 캐시 정비
  - 변경 내용: `api.ts` 도메인 분리, `queryKeys`/`threadCache` 타입 정합성 확보, invalidation 범위 축소
  - 완료 기준: 데이터 계층 구조 문서화 및 캐시 키/타입 불일치 해소
- Step 5: UI 토큰/테마/국제화 개선
  - 변경 내용: 테마 프리셋 정리, `highlightMatches` 안전성/a11y 개선, 하드코딩 문자열 제거
  - 완료 기준: UI 토큰/테마/i18n 개선 항목 적용 및 누락 키 점검 완료
- Step 6: 검증 및 정리
  - 변경 내용: 변경된 화면/플로우 수동 검증, 성능/에러 리스크 체크, 개선 결과 요약
  - 완료 기준: 변경 목록과 검증 결과를 문서에 기록

## Step 1 산출물 (우선순위/범위)
- P0 (즉시 대응 필요)
  - `highlightMatches`의 `dangerouslySetInnerHTML` 사용으로 XSS 위험 존재 (입력 신뢰 전제 위반 가능) `frontend/src/lib/highlightMatches.tsx`
  - `threadCache`가 feed 타입을 `ThreadDetail`로 가정해 entries 접근 시 런타임 불일치 가능 `frontend/src/lib/threadCache.ts`
  - `useHomeFeedState` 저장 로직 이중화로 상태 동기화 경합 위험 `frontend/src/hooks/useHomeFeedState.ts`
- P1 (이번 사이클 권장)
  - `HomeFeed`/`ThreadCard`/`ThreadDetailPage` 중복 로직 및 책임 과밀 `frontend/src/components/home/HomeFeed.tsx`, `frontend/src/components/home/ThreadCard.tsx`, `frontend/src/routes/ThreadDetailPage.tsx`
  - `ThreadEditor`의 외부 값 동기화 누락으로 stale UI 가능 `frontend/src/components/home/ThreadEditor.tsx`
  - 캐시 invalidation 과다 (`queryKeys`/`threadCache` 전반)로 성능 저하 가능 `frontend/src/lib/queryKeys.ts`, `frontend/src/lib/threadCache.ts`
  - 에러 처리 일관성 부족 (`api.ts`)으로 UX 불균일 `frontend/src/lib/api.ts`
  - 접근성/국제화 하드코딩 문자열 (SearchForm aria-label 등) `frontend/src/components/home/SearchForm.tsx`
- P2 (백로그)
  - `App`의 전역 책임 집중 및 라우트 가드 부재 `frontend/src/App.tsx`, `frontend/src/router.tsx`
  - `usePinchFontSize` 기본 줌 차단 리스크 `frontend/src/hooks/usePinchFontSize.ts`
  - 테마 프리셋 중복/정리 필요 `frontend/src/lib/uiTheme.ts`
  - `generated.ts` 스펙 불일치 (OpenAPI 미반영) `frontend/src/lib/api/generated.ts`

## 이번 사이클 범위

- Entry 리스트/드래그 렌더 공통 컴포넌트로 분리 (`frontend/src/components/home/EntryList.tsx`)
