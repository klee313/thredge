# 프론트 코드 리뷰 재검토 계획

## 배경/문제
- 37번 계획에 따라 단계별 리뷰를 수행했으나, 누락된 이슈가 있는지 재점검이 필요함
- 기존 후속 문서(38~46)를 참조하지 않고 동일한 방법으로 독립적으로 검토해야 함

## 목표
- 37번 계획의 단계별 흐름을 그대로 재현하여 새로운 관점의 이슈를 발굴한다
- 중복되지 않는 신규 개선 포인트를 분리해 정리한다
- 추가 검토가 필요한 영역이 있는지 판단한다

## 범위
- 포함: `frontend` 디렉토리 전반(구조, 상태 관리, 컴포넌트, API 연동, 성능, 테스트)
- 제외: 백엔드/인프라/데이터 파이프라인 상세 코드 리뷰
- 제한: 38~46번 문서는 참조하지 않는다

## 현재 동작 정리
- 37번 문서의 Step 0~6 흐름을 동일하게 적용한다
- 각 단계에서 "새로 발견된 항목"과 "이미 확인한 항목"을 구분해 기록한다
- 의심 구간은 질문 목록으로 분리해 추적 가능하게 정리한다

## 개선 방향
- 독립성: 기존 후속 문서의 결론에 영향을 받지 않고 37번 기준으로만 판단
- 완결성: 단계별 체크 포인트를 누락 없이 재검토
- 우선순위화: 새로 발견된 이슈를 영향도/난이도/효익 기준으로 분류

## 파일별 수정/리팩토링 포인트 (1차 재검토 결과)
### Step 0: 리뷰 범위 고정 및 기본 문서 확인
- (P2) `frontend/package.json`: `openapi:types` 결과물(`src/lib/api/generated.ts`) 최신화 보장 장치 부족 → CI/검증 스크립트로 drift 방지 검토
- (P2) `frontend/vite.config.ts`: `loadEnv`에 prefix 미제한(`''`) → 필요 환경변수만 허용하는 방식 검토
- (P3) `frontend/eslint.config.js`: `typescript-eslint` 규칙은 있으나 포맷 일관성 미보장 → 포맷 룰/도구(Prettier 등) 도입 검토

### Step 1: 엔트리포인트/라우팅/전역 스타일
- (P2) `frontend/src/main.tsx`: QueryClient/에러 처리 로직이 진입점에 집중 → `lib/queryClient.ts` 등으로 분리 고려
- (P2) `frontend/src/App.tsx`: 테마/전역 에러/인증/레이아웃이 한 컴포넌트에 집중 → `AppHeader`, `GlobalErrorBanner`, `AppLayout` 분리
- (P3) `frontend/src/router.tsx`: 라우트 구성/라지 로딩 선언부 집중 → 라우트 정의 파일 분리 검토

### Step 2: 핵심 화면/컴포넌트 구조
- (P1) `frontend/src/components/home/HomeFeed.tsx`: 상태/쿼리/뮤테이션/뷰가 단일 파일에 과밀 → Container/View 분리 및 훅 분해
- (P1) `frontend/src/components/home/ThreadCard.tsx`: IntersectionObserver/엔트리 로딩/드래그 UI 동시 처리 → `useVisibility` 훅 분리, Entry 섹션 분리
- (P1) `frontend/src/routes/ThreadDetailPage.tsx`: 디테일 화면의 액션/뮤테이션/렌더링 혼재 → 섹션 컴포넌트 분리 및 에러 처리 강화
- (P2) `frontend/src/components/home/CategoryFilterBar.tsx` vs `frontend/src/components/home/ThreadEditor.tsx`: 카테고리 검색/선택 UI 중복 → 공통 컴포넌트화
- (P3) `frontend/src/components/home/SearchForm.tsx`, `frontend/src/components/home/NewThreadComposer.tsx`, `frontend/src/components/common/Tooltip.tsx`: 들여쓰기/포맷 불일치 → 포맷 표준화 필요

### Step 3: 훅/상태 전파 경로
- (P1) `frontend/src/hooks/useHomeFeedState.ts`: URL 동기화 + 로컬스토리지 + UI 상태 혼합 → `url-state`/`draft-persistence` 분리
- (P2) `frontend/src/hooks/useThreadDetailState.ts`: Draft 유지 로직이 길고 중복 → 공통 persistence 유틸 도입 검토
- (P2) `frontend/src/hooks/useDateFilter.ts` & `frontend/src/hooks/useHomeFeedQueries.ts`: 날짜 포맷 로직 중복 → `lib/date.ts`로 통합
- (P2) `frontend/src/hooks/usePinchFontSize.ts`: `touchcancel` 미처리, 들여쓰기 불일치 → 이벤트 보강 및 포맷 통일
- (P2) `frontend/src/store/settingsStore.ts`: `nativeLanguage/targetLanguage/correctionEnabled/coachTone` 미사용 → 제거 또는 UI 연계 결정 필요

### Step 4: 데이터 계층/API 유틸
- (P0) `frontend/src/lib/highlightMatches.tsx`: `dangerouslySetInnerHTML` 사용 → 신뢰 모델 문서화 및 주석 지침 유지(기존 경고 주석 삭제 금지)
- (P2) `frontend/src/lib/threadCache.ts`: 캐시 업데이트 유틸이 누적됨 → 공통 헬퍼/테스트 추가로 안정성 강화

### Step 5: UI 토큰/국제화
- (P2) `frontend/src/lib/uiTokens.ts`: 스타일 토큰 문자열이 커짐 → 컴포넌트별 토큰 분리 또는 테마 레이어 도입 검토
- (P2) `frontend/src/locales/*.json`: 설정 관련 키(`nativeLanguage`, `targetLanguage` 등) 사용처 부재 → 키 정리 또는 기능 복원 필요

## 우선순위 기준
- P0: 보안/데이터 손상/중대한 런타임 위험
