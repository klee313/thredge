# 프론트 코드 재점검 리뷰 계획 2

## 배경/문제
- 37번 계획에 따른 1차 리뷰 이후, 추가적으로 남아 있을 수 있는 품질/구조 리스크를 재확인할 필요가 있음
- 기존 리뷰 결과에 의존하지 않고 동일 절차를 재실행해 누락 지점을 탐색해야 함

## 목표
- 37번 계획의 단계별 절차를 다시 수행해 남은 개선 포인트를 식별한다
- 이전 결과와 무관하게 객관적인 체크리스트 기반으로 문제 지점을 재발견한다
- 즉시 조치 가능 항목과 중장기 개선 항목을 구분한다

## 범위
- 포함: `frontend` 디렉토리 전반(구조, 상태 관리, 컴포넌트, API 연동, 성능, 테스트)
- 제외: 백엔드/인프라/데이터 파이프라인 상세 코드 리뷰
- 제외: 38, 39번 문서 결과의 재사용/참조

## 현재 동작 정리
- 엔트리포인트/라우팅/화면 구성/상태/데이터 계층 순으로 프론트 흐름을 재정리한다
- 핵심 경로 위주로 구조/책임/결합도를 확인하며, 불명확한 지점은 질문으로 기록한다
- 리뷰 범위와 관찰 기록을 분리해 추적 가능하도록 관리한다

## 개선 방향
- 유지보수성: 책임 분리, 결합도 낮추기, 재사용성 높이기
- 안정성: 경계 조건 처리, 에러 핸들링 일관성 강화
- 성능: 렌더링/네트워크 병목 요인 확인 및 완화 포인트 탐색
- 테스트성: 단위/통합 테스트 추가 여지 재점검

## 검증 계획
- 정적 리뷰 결과만 정리하고 실제 변경은 하지 않는다
- 필요 시 핵심 화면에 대해 간단한 수동 동작 확인 절차를 제안한다

## 재점검 결과 (Step 0~4, 1차)
### Step 0: 리뷰 범위/도구 체인
- 특이사항 없음 (스크립트/린트/타입 설정 상 충돌 지점 미발견)

### Step 1: 엔트리/라우팅/전역 스타일
- 설정 페이지에서 테마 프리뷰가 저장 전에도 전역 CSS 변수에 반영됨. 저장하지 않고 화면 이동 시 테마가 유지될 수 있어 스토어 값과 UI가 불일치할 가능성 있음
  - 후보 파일: `frontend/src/routes/SettingsPage.tsx`
  - 개선 방향: 저장/취소 시점 기준으로 테마 적용을 분리하거나, 언마운트 시 원복 처리

### Step 2: 핵심 컴포넌트/공통 컴포넌트
- Tooltip이 hover 전용이라 키보드 포커스/접근성 대응이 부족함 (role만 존재하고 aria 연결 및 focus 트리거 부재)
  - 후보 파일: `frontend/src/components/common/Tooltip.tsx`
  - 개선 방향: focus-visible 트리거, aria-describedby 연결, 터치 환경 대비 고려
- 카테고리 생성 흐름에서 입력값과 제출 시점이 분리되어 있어 최신 입력이 아닌 값이 제출될 수 있음
  - 후보 파일: `frontend/src/components/home/ThreadEditor.tsx`, `frontend/src/components/home/HomeFeed.tsx`, `frontend/src/routes/ThreadDetailPage.tsx`
  - 개선 방향: ThreadEditor에서 `onCategorySubmit(value)` 형태로 최신 값 직접 전달, 상위에서는 상태 의존 대신 파라미터 기반 처리
- Entry/Reply/Thread 입력 컴포넌트에 debounced 로컬 상태 동기화 로직이 중복되고, 동작 차이가 누적됨
  - 후보 파일: `frontend/src/components/home/EntryComposer.tsx`, `frontend/src/components/home/ReplyComposer.tsx`, `frontend/src/components/home/EntryEditor.tsx`, `frontend/src/components/home/NewThreadComposer.tsx`, `frontend/src/components/home/ThreadEditor.tsx`
  - 개선 방향: 공통 훅/유틸로 통합해 동기화 규칙(제출 후 초기화, 외부 업데이트 반영 시점) 일관화
- 피드 카드/디테일 화면에서 스레드/엔트리 액션 wiring이 유사하지만 별도 구현으로 유지되어 드리프트 위험이 큼
  - 후보 파일: `frontend/src/components/home/ThreadCard.tsx`, `frontend/src/routes/ThreadDetailPage.tsx`
  - 개선 방향: 공통 컨테이너/훅으로 액션 조합 및 캐시 업데이트 로직을 공유

### Step 3: 훅/상태 전파
- 날짜 파서가 유효한 날짜인지 검증하지 않아 잘못된 날짜가 보정되어 필터 결과가 왜곡될 수 있음
  - 후보 파일: `frontend/src/hooks/useDateFilter.ts`
  - 개선 방향: 입력값 유효성 체크(월/일 범위) 후 실패 시 null 처리
- 카테고리 경로 파싱에서 `decodeURIComponent` 예외가 처리되지 않아 잘못된 URL 파라미터로 앱이 깨질 수 있음
  - 후보 파일: `frontend/src/hooks/useHomeFeedState.ts`
  - 개선 방향: 안전 디코딩(try/catch) 및 실패 시 원문 유지/필터링
- 탭 전환 시 검색 쿼리를 유지하도록 되어 있어, UI 탭은 “새 스레드”인데 리스트는 검색 결과를 보여주는 상태가 가능함
  - 후보 파일: `frontend/src/hooks/useHomeFeedState.ts`, `frontend/src/components/home/HomeFeed.tsx`
  - 개선 방향: 탭 전환 정책 명확화(새 탭 전환 시 검색 해제 or 검색 탭 고정)

### Step 4: 데이터 계층/API 유틸
- 스레드 pin/unpin 시 피드 캐시만 즉시 갱신하고 검색 캐시는 갱신하지 않아 화면 간 일관성이 깨질 수 있음
  - 후보 파일: `frontend/src/lib/threadCache.ts`
  - 개선 방향: `setThreadPinnedInFeed`에서 searchRoot까지 동일하게 업데이트

### Step 5: UI 토큰/유틸/국제화
- `disableLinks` 옵션이 linkify 단계 이전에 적용되지 않아, 링크 비활성화 의도가 무시될 수 있음
  - 후보 파일: `frontend/src/lib/highlightMatches.tsx`
  - 개선 방향: `disableLinks`일 때는 linkify를 스킵하고 기존 HTML만 유지
- Tooltip이 hover 중심 UX라 키보드 포커스 시 표시가 되지 않을 수 있음
  - 후보 파일: `frontend/src/components/common/Tooltip.tsx`
  - 개선 방향: focus-within 표시 처리 및 aria 연결 보강
