# 프론트 코드 리뷰 재점검 계획 2

## 배경/문제
- 37번 계획에 따라 리뷰를 수행했고, 이후 38~41번 후속 문서가 생성됨
- 후속 문서와 무관하게 37번 계획만으로 다시 리뷰를 수행해 누락 항목이 있는지 확인할 필요가 있음
- 동일한 단계 흐름으로 재점검해 추가 리스크나 개선 지점을 객관적으로 확보하고 싶음

## 목표
- 37번 계획의 단계 흐름을 그대로 재수행해 누락된 이슈를 찾아낸다
- 개선/리스크 항목을 단계별로 재정리하고, 추가 검토 필요 항목을 분리한다
- 후속 개선 문서(38~41)와 독립적인 결과물을 만든다

## 범위
- 포함: `frontend` 디렉토리 전반(구조, 상태 관리, 컴포넌트, API 연동, 성능, 테스트)
- 제외: 백엔드/인프라/데이터 파이프라인 상세 코드 리뷰
- 제외: 38~41번 문서를 참조하거나 비교하는 작업

## 현재 동작 정리
- 37번 계획의 단계 정의와 대상 파일 목록만을 기준으로 재검토를 진행한다
- 매 단계에서 확인 포인트를 체크하고, 발견 이슈를 “추가 발견/재확인/보류”로 분류한다
- 단계별 산출물은 누락 여부를 판단하기 위한 요약 리스트로 기록한다

## 개선 방향
- 37번과 동일한 원칙을 적용하되, 이번 결과는 “추가 발견”에 집중한다
- 유지보수성/안정성/성능/테스트성 관점에서 중복 없이 핵심만 기록한다
- 단기 조치 후보와 중장기 개선 후보를 분리해 정리한다

  - 잠재 리스크: 편집 상태 동기화 실패, 포커스/드래프트 손실, 이벤트 핸들러 중복/누락
  - 필요 작업: 공통 컴포저 인터페이스 정의, 상태 소유권/제어 방식 결정, 단계적 교체 계획 수립
- 드래그 관련 로직 추가 분리 및 테스트 확장
  - 보류 이유: 입력/제스처 로직은 회귀 가능성이 높고, 안정성 검증 없이는 변경이 위험
  - 영향 범위: `EntryCard`, `useEntryDragState`, 드롭 인디케이터/이동 API 호출
  - 잠재 리스크: 드래그 종료 누락, 스크롤/터치 충돌, 드롭 위치 계산 오류
