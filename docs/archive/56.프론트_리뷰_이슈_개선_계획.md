# 프론트 리뷰 이슈 개선 계획

## 배경/문제
- 37번 기준 재수행 리뷰(55번)에서 중 이상 우선순위 이슈가 발견됨
- 현재 구조는 컨테이너/훅 책임이 과도하게 결합되어 변경 비용과 리스크가 큼
- 일부 툴링 설정 누락으로 lint 안정성이 떨어질 수 있음

## 목표
- 리뷰에서 발견된 중 이상 이슈를 우선 해결한다
- 코드 책임 분리와 변경 영향 범위를 축소한다
- lint/타입 체크 경계를 명확히 한다

## 범위
- 포함:
  - ESLint 타입 체크 대상 파일 범위 정리
  - 홈 피드 컨트롤러/카드 구성의 책임 분리 리팩토링
  - 쓰레드 디테일 컨트롤러의 기능 분리
  - draft 저장/복원 로직 분리
- 제외:
  - UI/기능 추가
  - API 동작 변경
  - 백엔드 수정

## 현재 동작 정리
- `useHomeFeedController`/`useThreadDetailController`가 상태/쿼리/뮤테이션/에러를 단일 훅에서 처리
- `ThreadCardContainer`가 데이터/상태/뮤테이션/액션을 과도하게 결합
- draft 저장/복원 로직이 상태 훅 내부에 밀집
- ESLint 타입 체크 대상에서 `vitest.config.ts`가 제외됨

## 개선 방향
- 책임 분리: 컨트롤러/뷰/상태/뮤테이션 레이어를 구분
- 테스트성 강화: 핵심 훅을 작은 단위로 분리해 검증 가능하게
- 툴링 안정성: lint가 안정적으로 모든 대상 파일을 포함하도록 구성

## 단계별 계획
- Step 0: 툴링/설정 개선
  - 변경: `tsconfig.node.json`에 `vitest.config.ts` 포함 또는 도구용 tsconfig 추가
  - 완료 기준: ESLint 타입 기반 검사 대상 누락 없음
- Step 1: HomeFeed 컨트롤러 분리
  - 변경: 상태/쿼리/뮤테이션/액션 조합을 하위 훅으로 분리
  - 완료 기준: `useHomeFeedController`의 책임 축소 및 반환 구조 단순화
- Step 2: ThreadCard 컨테이너 분리
  - 변경: `ThreadCardContainer`의 props/액션 조합을 분리된 어댑터/훅으로 이동
  - 완료 기준: 컨테이너가 최소 역할만 수행
- Step 3: ThreadDetail 컨트롤러 분리
  - 변경: 편집/엔트리/카테고리/드래그 로직을 분리 훅으로 이동
  - 완료 기준: `useThreadDetailController`에서 핵심 orchestration만 유지
- Step 4: Draft persistence 분리
  - 변경: `useHomeFeedState`/`useThreadDetailState`에서 persistence 책임 분리
  - 완료 기준: 상태 훅에서 저장/복원 사이드이펙트 제거 또는 최소화
- Step 5: 피드 엔트리 로딩 최적화
  - 변경: 프리패칭/묶음 로딩/가상화 중 선택하여 적용
  - 완료 기준: 피드 스크롤 시 동시 쿼리/렌더링 부하 완화 근거 확인
- Step 6: 정리 및 검증
  - 변경: 리팩토링 후 타입 체크/테스트 스모크
  - 완료 기준: 빌드/테스트/린트 통과 또는 차이점 명시
