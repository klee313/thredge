# todo 카테고리 최초 테이블 렌더링 기능 계획

## 배경/문제
- todo 카테고리 스레드의 본문이 Markdown 테이블인 경우, 현재는 일반 본문으로만 보이며 할 일 관리 정보가 UI로 구조화되어 있지 않다.
- 사용자는 할 일, 데드라인, 중요도, 블로커 등 핵심 정보를 한눈에 보고 즉시 액션(완료, AI 도움)을 수행하기 어렵다.

## 목표
- todo 카테고리의 가장 오래된 스레드 본문이 Markdown 테이블이면, 각 행을 전용 카드/리스트 형태로 화면 좌측 상단(모바일은 최상단)에 예쁘게 렌더링한다.
- 각 행에 6개 항목(할일 내용, 데드라인, 중요도, 블로커, 블로커 해결 방식 제안, 완료 처리)을 제공한다.
- AI 버튼은 빈 값이 있을 때 가이드를 제공하고, 모두 채워졌다면 적절한 프롬프트로 대안 제안을 받는다.
- 완료 처리 시 테이블 본문에도 완료 표시를 반영한다.
- 수정 버튼을 제공하고, 버튼 클릭 시 해당 스레드카드 상세페이지가 수정 상태로 열린다.
- 본문이 테이블이 아닐 경우 “테이블이 아닙니다” 안내를 표시한다.
- 수정 모드 진입 시 예시 테이블을 자동 삽입한다.

## 범위
- 포함
  - todo 카테고리 스레드 중 **가장 오래된 create** 스레드의 본문 파싱 및 UI 렌더링
  - Markdown 테이블 → 구조화 데이터 파싱
  - 좌측 상단(모바일 최상단) 고정 배치 UI
  - AI 도움 흐름(가이드 표시 → 모두 채워짐 시 대안 제안)
  - 설정 페이지에 AI 종류 선택 및 API Key 입력 UI 추가
  - AI 사용 시 키 미입력 상태 가이드 노출
  - user 테이블에 AI API Key 저장용 필드 1개 추가
  - user 테이블에 AI 종류 저장용 필드 1개 추가
  - 블로커 해결 방법 추천 결과를 해당 스레드 본문(테이블)에 **덮어쓰기**로 반영
  - 수정 버튼 제공 및 상세페이지 수정 모드로 이동
  - 테이블 미지원 본문에 대한 안내 문구 표시
  - 수정 모드 진입 시 예시 테이블 자동 추가
  - 완료 처리 버튼 동작(현행 완료 처리 방식에 연동)
- 제외
  - todo 이외 카테고리 적용
  - 다중 테이블/중첩 테이블 지원 확대
  - AI 모델/백엔드 엔드포인트 신규 설계 (기존 AI 기능을 활용하는 범위로 제한)
  - AI 종류를 사용자 설정으로 저장/변경하는 기능 (하드코드로 고정)

## 현재 동작 정리
- 스레드 목록에서 todo 카테고리 스레드는 일반 본문/마크다운 렌더링만 지원한다.
- AI 기능은 특정 UI에서만 사용되며, 테이블 기반 행 단위 안내 흐름은 없다.
- 완료 처리 버튼은 스레드/댓글 단위에서만 제공되거나, 별도 흐름으로 처리된다.
- 설정 페이지에서 AI 종류/키 입력은 제공되지 않는다.
- user 테이블에 AI API Key 전용 저장 필드는 없다.
- user 테이블에 AI 종류 저장 필드는 없다.

## 개선 방향
- 단일 진입점: todo 카테고리의 **정상(삭제/숨김 제외) 스레드 중 created_at 단일 정렬** 기준으로 가장 오래된 스레드 본문을 단일 소스로 사용한다.
- 표준화된 파싱: Markdown 테이블의 헤더/행을 안정적으로 파싱하고, 필수 컬럼을 매핑한다.
- 점진적 AI 지원: 빈 값 가이드 → 모두 채워짐 시 대안 제안으로 UX 분기.
- 반응형 배치: 데스크톱은 좌측 상단 고정, 모바일은 최상단 고정.
- 설정 연동: AI 사용 전 종류 선택 및 API Key 입력을 요구하고, 미입력 시 가이드를 노출한다.
- 키 저장: user 테이블에 단일 필드로 저장하고, 저장 시 암호화/마스킹을 적용한다.
- AI 종류 고정: 지원 모델/프로바이더는 하드코딩 목록을 제공하되, 사용자별 선택 값은 user 테이블에 저장한다.
- AI 추천 결과 반영: 추천된 블로커 해결 방법을 스레드 본문 테이블에 업데이트하고, UI에서도 즉시 반영한다.
- 완료 상태 반영: 완료 처리 시 테이블 셀에도 완료 표시(체크/상태값 등)를 덮어쓰기 반영한다.
- 기능 분리: todo 전용 파서/컴포넌트/서비스를 분리하고 기존 코드와 결합도를 최소화한다.
- 수정 흐름 통합: 카드 내 수정 버튼 → 상세페이지 수정 모드로 연결하고, 테이블 예시 삽입을 통해 빠른 작성 유도.

## 단계별 계획
- Step 1) 데이터/렌더링 진입점 파악
  - todo 카테고리 스레드 조회 흐름, 생성일 정렬/필터 지점 확인
  - 완료 기준: 가장 오래된 todo 스레드 1건을 안정적으로 가져옴
- Step 2) Markdown 테이블 파서 설계 및 구현
  - 헤더 매핑(할일, 데드라인, 중요도, 블로커, 제안, 완료) 규칙 정의
  - 누락/빈 값 처리 규칙 정의
  - 완료 기준: 표준 테이블 1개를 구조화 데이터로 변환 가능
- Step 3) UI 컴포넌트 구성
  - 좌측 상단(모바일 최상단) 영역에 리스트/카드 렌더링
  - 각 행의 6개 항목과 버튼 배치, 스타일 적용
  - 수정 버튼 추가 및 상세페이지 수정 모드로 연결
  - 완료 기준: 대표 시나리오에서 화면 레이아웃 정상 표시
- Step 4) AI 가이드 및 제안 흐름 연동
  - 빈 값 존재 시 “채우기 가이드” 표시
  - 모두 채워짐 시 프롬프트 구성 후 대안 제안 요청
  - 프롬프트 템플릿 작성 및 샘플 제공
  - 추천 결과를 스레드 본문 테이블에 덮어쓰는 업데이트 흐름 정의
  - 완료 기준: 가이드/제안 분기와 응답 표시 확인
- Step 5) 설정 페이지 AI 입력 UI 추가
  - AI 종류 선택 드롭다운 및 API Key 입력 필드 배치
  - 키 미입력 상태에서 AI 기능 호출 시 안내 UI 표시
  - 완료 기준: 설정 저장/불러오기와 가이드 노출 확인
- Step 6) user 테이블 스키마 및 저장 로직 반영
  - user 테이블에 API Key 저장 필드 1개 추가 (예: `ai_api_key_encrypted` TEXT, NULL 허용)
  - user 테이블에 AI 종류 필드 1개 추가 (예: `ai_provider` TEXT, NULL 허용)
  - 저장 시 서버에서 암호화 후 저장, 조회 시 마스킹된 값만 반환
  - 설정 저장/조회 API에서 필드 읽기/쓰기 연결
  - 완료 기준: 저장 후 재로그인/새로고침 시 값 복원 확인
- Step 7) 완료 처리 버튼 연동
  - 행 단위 완료 처리 동작을 기존 완료 처리 로직에 연결
  - 완료 표시를 테이블 셀에도 반영(예: 체크/상태값)
  - 완료 기준: 완료 처리 후 UI 및 테이블 본문 동기 갱신 확인
- Step 8) 테이블 미지원 본문 및 예시 테이블 처리
  - 본문이 테이블이 아니면 “테이블이 아닙니다” 안내 표시
  - 수정 모드 진입 시 예시 테이블을 자동 삽입
  - 완료 기준: 안내 문구 및 예시 테이블 삽입 확인

## 리스크 및 대응
- 테이블 포맷 변형(컬럼 순서/이름)으로 파싱 실패 가능
  - 대응: 헤더 매핑 유연화 및 필수 컬럼 미존재 시 안전한 폴백 처리
- 가장 오래된 스레드 조회가 성능/정확도에 영향 가능
  - 대응: 쿼리/정렬 기준 명확화 및 최소 조회로 제한
- AI 응답 지연/실패 시 UX 저하
  - 대응: 로딩/실패 상태 처리, 재시도 안내
- API Key 보관/입력 UX가 불편하거나 노출 위험
  - 대응: 입력 마스킹, 안내 문구, 최소 권한 저장 정책 검토
- user 테이블 스키마 변경에 따른 마이그레이션 실패 가능
  - 대응: 롤백 가능 마이그레이션 작성 및 배포 전 검증
- 수정 모드 예시 테이블 자동 삽입으로 사용자 본문이 의도치 않게 변경될 수 있음
  - 대응: 수정 전 알림/되돌리기 제공 또는 삽입 위치를 명확히 표시

## 프롬프트 예시
- 빈 값 가이드용(입력 유도)
  - 시스템: 너는 할 일 관리 코치다. 사용자가 빈 칸을 채울 수 있도록 질문을 짧고 명확하게 제시한다.
  - 사용자: 아래 할 일 행의 빈 칸을 채우기 위해 필요한 질문을 3개만 제시해줘.\n할일: {할일}\n데드라인: {데드라인}\n중요도: {중요도}\n블로커: {블로커}
- 블로커 해결 방법 추천용(모두 채워짐)
  - 시스템: 너는 실용적인 문제 해결 코치다. 블로커를 해소하는 실행 가능한 방법을 2~3개 추천한다.
  - 사용자: 아래 할 일의 블로커를 해결하기 위한 방법을 추천해줘. 각 방법은 2문장 이내로.\n할일: {할일}\n데드라인: {데드라인}\n중요도: {중요도}\n블로커: {블로커}\n현재 해결 방식: {해결방식}

## 예시 테이블 포맷
수정 모드 진입 시 아래 예시 테이블을 자동 삽입한다.

```markdown
| 할일 | 데드라인 | 중요도 | 블로커 | 해결 방식 | 완료 |
| --- | --- | --- | --- | --- | --- |
| 예: 로그인 페이지 카피 수정 | 2026-02-05 | 높음 | 디자인 승인 지연 | (빈칸) | n |
```

## 검증 계획
- 파서 단위 테스트(표준 테이블/누락 컬럼/빈 값 케이스)
- 대표 todo 스레드로 UI 렌더링 수동 확인
- 모바일/데스크톱 레이아웃 수동 확인
- AI 가이드/제안 흐름 수동 확인
- 완료 처리 버튼 클릭 후 상태 갱신 확인
