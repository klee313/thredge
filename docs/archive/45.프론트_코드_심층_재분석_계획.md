# 프론트 코드 심층 재분석 계획

## 배경/문제
- 44번 재실행 계획 이후, 기존 결과와 무관하게 더 깊은 수준의 구조/품질/안정성 점검이 필요함
- 단일 패스로는 놓칠 수 있는 이슈가 많아, 분석 단계를 분리해 체계적으로 진행해야 함

## 목표
- 프론트 전반의 안정성/보안/성능/유지보수/접근성 리스크를 최대한 발굴
- 파일 단위로 재현 가능한 근거(코드 위치)를 남겨 개선 후보를 구체화
- 발견 사항을 “즉시 수정/중기 개선/장기 구조 개선”으로 분류

## 범위
- 포함: `frontend` 전체(라우팅, 상태관리, 데이터 계층, UI 컴포넌트, 유틸, 테스트)
- 제외: 백엔드 상세 구현, 인프라/배포 파이프라인

## 현재 동작 정리
- 37번 계획의 Step 0~6 범위를 기준으로 하되, 분석 깊이를 확장
- 후속 문서(38~43) 내용은 참조하지 않고 코드만 기준으로 관찰

## 개선 방향
- 증거 기반: 모든 지적은 파일/구문 단위로 근거를 남김
- 계층별 분리: “설정/엔트리/라우팅/상태/데이터/컴포넌트/유틸/테스트”로 단계 구분
- 리스크 분류: 보안/정합성/성능/UX/접근성/테스트 공백으로 태깅

## 단계별 계획
- Phase 1: 설정/엔트리/라우팅 점검
  - 대상: `frontend/README.md`, `frontend/package.json`, `frontend/vite.config.ts`, `frontend/tsconfig*.json`, `frontend/eslint.config.js`, `frontend/src/main.tsx`, `frontend/src/App.tsx`, `frontend/src/router.tsx`, `frontend/src/routes/**`
  - 완료 기준: 빌드/런타임 전제, 라우팅 구조, 전역 에러/테마/상태 초기화 리스크 목록
- Phase 2: 상태/훅/스토어 점검
  - 대상: `frontend/src/hooks/**`, `frontend/src/store/**`
  - 완료 기준: 상태 소유권, 비동기 경합, 스토리지 동기화, 훅 간 결합 리스크 정리
- Phase 3: 데이터 계층/캐시/정합성 점검
  - 대상: `frontend/src/lib/api.ts`, `frontend/src/lib/queryKeys.ts`, `frontend/src/lib/threadCache.ts`, `frontend/src/lib/useDebouncedValue.ts`, `frontend/src/lib/entryOrder.ts`, `frontend/src/lib/entryDepth.ts`
  - 완료 기준: API 에러 경로, 캐시 갱신 범위, 데이터 정합성 위험 정리
- Phase 4: 핵심 화면/컴포넌트 심층 점검
  - 대상: `frontend/src/components/home/**`, `frontend/src/components/common/**`, `frontend/src/routes/**`
  - 완료 기준: 복잡도/상태 결합/재사용성/렌더 비용/UX 이슈 목록
- Phase 5: UI 토큰/국제화/보안/접근성 점검
  - 대상: `frontend/src/lib/uiTheme.ts`, `frontend/src/lib/uiTokens.ts`, `frontend/src/i18n.ts`, `frontend/src/locales/**`, `frontend/src/lib/highlightMatches.tsx`
  - 완료 기준: i18n 관리, 테마 정책, XSS/HTML 렌더링 위험, 접근성 공백 정리
- Phase 6: 테스트 공백 및 우선순위 정리
  - 대상: `frontend/src/setupTests.ts`, `frontend/src/components/**` 테스트 파일, 현재 테스트 커버리지 간접 점검
  - 완료 기준: 테스트 부족 영역과 우선순위 제안
