# todo 테이블 마이그레이션 계획

## 배경/문제
- 홈 프론트페이지의 todo 렌더링은 `todo` 카테고리의 **가장 오래된 스레드 본문 Markdown 테이블**을 파싱하는 방식에 의존한다.
- 현재는 todo 데이터가 `threads.body`에 문자열로만 존재해 구조적 조회/정렬/부분 업데이트가 어렵다.
- `todo` 전용 데이터 모델이 없어 API/프론트 로직이 스레드/카테고리 로직에 강하게 결합되어 있다.

## 목표
- `todos` 테이블을 추가하여 todo 항목을 **정규화된 구조**로 관리한다.
- 홈의 todo 위젯이 `todo` 카테고리 스레드가 아닌 `todos` 테이블 데이터를 직접 렌더링하도록 전환한다.
- 기존 Markdown 테이블 기반 데이터는 **마이그레이션하지 않고 폐기**한다.
- 정렬은 `deadline` 기준으로만 제공한다.
- `deadline` 입력은 캘린더 UI를 제공한다.
- 중요도 입력은 `파/초/노/빨` 4가지로 제한한다.

## 범위
- 포함 범위
  - `todos` 테이블 설계 및 마이그레이션 스크립트 추가
  - todo 조회/수정 API 추가 및 프론트 위젯 연결
  - 기존 `/api/threads/todo/oldest` 사용 흐름 정리 또는 대체
- 제외 범위
  - 기존 `todo` 카테고리 스레드 본문 데이터 백필
  - todo UX/디자인 변경(현재 UI 유지)
  - todo 기능의 다중 리스트/프로젝트 관리 기능 확장
  - 기존 스레드/댓글 데이터 모델의 대규모 리팩터링

## 현재 동작 정리
- 프론트 홈 위젯
  - `frontend/src/hooks/useHomeFeedQueries.ts`가 `/api/threads/todo/oldest` 호출
  - `frontend/src/components/home/TodoThreadWidget.tsx`가 `todoTable` 파서로 Markdown 테이블을 파싱하고 렌더링
  - 완료 토글/AI 해결책 반영은 `threads` PATCH로 본문 테이블을 수정
- 프론트 스레드 상세
  - `frontend/src/hooks/useThreadDetailController.ts`가 `todoExample=1`일 때 본문에 예시 테이블 자동 삽입
- 백엔드
  - `backend/src/main/kotlin/com/thredge/backend/api/ThreadController.kt`의 `/api/threads/todo/oldest`
  - `ThreadService.getOldestThreadByCategory`가 `todo` 카테고리의 가장 오래된 스레드를 가져옴
- DB
  - `threads`, `categories`, `thread_categories`만 존재. todo 전용 테이블 없음.

## 개선 방향
- todo는 스레드 본문이 아닌 **독립 테이블**로 관리한다.
- 레거시 데이터는 **폐기**하고, 새 데이터만 `todos`에 저장한다.

## 단계별 계획
- Phase 1: 스키마 설계
  - 작업 내용
    - `todos` 테이블 스키마 확정
    - 필수 컬럼 정의: `id`, `owner_id`, `task`, `deadline(date)`, `priority(enum: blue/green/yellow/red)`, `blocker`, `solution`, `done`, `created_at`, `updated_at`
    - 정렬 기준: `deadline` 단일 정렬
  - 완료 기준
    - Postgres/H2 마이그레이션 파일 작성 초안 확정

- Phase 2: 백엔드 마이그레이션
  - 작업 내용
    - Flyway 마이그레이션으로 `todos` 테이블 추가
  - 완료 기준
    - 신규 todo가 `todos`에 저장됨을 샘플 계정으로 확인

- Phase 3: API 추가
  - 작업 내용
    - `GET /api/todos` (홈 위젯 조회용)
    - `PATCH /api/todos/{id}` (완료/해결방식 등 부분 업데이트)
    - `POST /api/todos` (행 추가)
    - 필요 시 `PUT /api/todos/bulk` (일괄 업데이트)
  - 완료 기준
    - todo 위젯에서 필요한 데이터 및 업데이트가 API만으로 가능

- Phase 4: 프론트 전환
  - 작업 내용
    - `fetchOldestTodoThread` 대신 `fetchTodos` 추가
    - `TodoThreadWidget`에서 `todos` 목록 렌더링
    - 완료 토글/AI 적용 시 `todos` API 호출로 변경
    - `deadline` 입력은 캘린더 UI로 제공
    - `priority` 입력은 `파/초/노/빨`만 선택 가능하도록 제한
    - 레거시 스레드 링크는 유지(“열기/편집” 버튼은 기존 스레드로 연결 가능)
  - 완료 기준
    - 홈 todo 위젯이 `threads` 의존 없이 동작

- Phase 5: 레거시 정리
  - 작업 내용
    - `/api/threads/todo/oldest` 사용처 제거 또는 deprecated 처리
    - `todoTable` 파서 사용 범위 축소/정리
  - 완료 기준
    - 레거시 의존 제거

## 리스크 및 대응
- 레거시 데이터 폐기로 인한 사용자 혼란
  - 대응: 릴리즈 노트/공지에 “기존 todo 기록은 유지되지 않음” 명시

## 검증 계획
- 자동 검증
  - API 단위 테스트(조회/업데이트/생성)
- 수동 검증
  - 홈 화면에서 todo 목록이 정상 표시되는지 확인
  - 완료 토글 및 AI 추천 반영이 `todos`에 저장되는지 확인
  - 레거시 `todo` 스레드 링크 클릭 시 정상 이동 확인

## 결정 필요 사항
- 정렬 기준은 `deadline` 단일 정렬로 고정
- `deadline` 타입은 `date`로 확정
- `priority`는 `파/초/노/빨` 4단계로 고정
