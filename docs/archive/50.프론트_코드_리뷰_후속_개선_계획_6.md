# 프론트 코드 리뷰 후속 개선 계획 6

## 배경/문제
- 37번 리뷰 절차를 다시 수행하며 다수의 수정 후보가 식별됨
- 기존 후속 문서를 참조하지 않고 새로 도출된 항목을 기준으로 정리해야 함
- 항목이 많아 누락/중복 없이 단계별로 정리된 실행 계획이 필요함

## 목표
- 지금까지 언급된 모든 수정 필요 내역을 한 문서에 체계적으로 정리한다
- Step 0~6 흐름에 맞춰 항목을 분류하고, 우선순위와 검증 기준을 명시한다
- 상단 항목부터 순차적으로 처리할 수 있는 실행 순서를 제공한다

## 범위
- 포함: `frontend` 디렉토리 전반(설정/라우팅/컴포넌트/훅/유틸/테스트)
- 제외: 백엔드/인프라/데이터 파이프라인 상세 수정
- 참고: 38~48번 문서는 본 작업에서 참조하지 않는다

## 현재 동작 정리
- 프론트는 React + Vite + React Query + i18n 기반 구조
- 홈 피드/스레드 상세/아카이브/설정/관리자 페이지로 구성
- 상태는 훅과 zustand(store)로 분산 관리되며 일부 draft는 localStorage에 저장됨
- 컴포넌트/훅/유틸 모듈이 크고 상호 의존성이 높아 개별 변경 시 영향 범위가 큼

## 개선 방향
- 안정성/보안: XSS 및 CSP 충돌 가능 지점을 우선 제거/완화
- 사용자 경험: 입력/포커스/드래그/날짜 표기 등 일관성 개선
- 데이터 정합성: 캐시/쿼리/URL 상태 동기화의 부작용 최소화
- 유지보수성: 과도한 prop/상태 결합 지점을 분리해 변경 비용 축소
- 테스트성: 핵심 유틸과 캐시 로직에 대한 최소 테스트 보강
