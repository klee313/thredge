# 프론트 리뷰 수정 일괄 반영 계획

## 배경/문제
- 51번 재점검에서 도출된 수정 제안 항목을 실제 코드로 반영할 필요가 있음
- 현재는 정적 리뷰 수준이라, 코드 구조/에러 처리/테마/상태 동기화 등에서 개선 여지가 남아 있음

## 목표
- 51번 문서의 수정 제안 항목을 가능한 범위에서 모두 반영한다
- 코드 변경 범위를 명확히 하고, 리스크를 줄이는 방향으로 점진적 개선을 적용한다
- 변경 이후 동작 일관성과 유지보수성을 높인다

## 범위
- 포함: `frontend` 전반의 설정, 훅/컨트롤러 구조, 데이터 계층 유틸, UI 토큰/테마, i18n 동기화
- 제외: 백엔드 API 변경, 서버/DB 스키마 변경, 실제 디자인 전면 개편

## 현재 동작 정리
- 빌드/타입체크는 `tsc -b` 기반이지만 `composite` 설정 없음
- 요청 유틸의 에러 메시지 파싱이 `requestJson`과 `requestEmpty`에서 일관되지 않음
- Home/Detail 컨트롤러가 상태/쿼리/뮤테이션을 과밀하게 보유
- draft 저장 및 URL 상태 동기화가 분산된 effect로 관리됨
- 테마/토큰/국제화 정책이 코드 곳곳에 분산됨

## 개선 방향
- 설정: 타입체크 안정성 확보 및 툴 체인 전제 명확화
- 상태/구조: 컨트롤러 책임 축소 및 공통 로직 분리
- 데이터 계층: 에러 메시지/캐시 갱신 규칙 일관화
- UI/국제화: 스타일 토큰/테마/언어 설정 정책 정리

## 단계별 계획
- Step 0: 설정/스크립트 안정화
  - `tsconfig.*`에 `composite` 적용 여부 판단 및 반영
  - `openapi:check`/패키지 매니저 정책 확인용 주석/문서 보강
  - 완료 기준: 타입체크/빌드 전제 명확화
- Step 1: 에러 처리/요청 유틸 정비
  - `requestEmpty`에서 에러 본문/메시지 파싱 보강
  - 글로벌/로컬 에러 정책 최소한의 일관성 확보
  - 완료 기준: 동일 실패 케이스에서 메시지 경로가 통일됨
- Step 2: 컨트롤러/훅 책임 분리
  - Home/Detail 컨트롤러에서 UI 전달용 묶음 분리
  - 중복 액션/데이터 조합 로직 공통화 검토
  - 완료 기준: 주요 컴포넌트 props 경량화
- Step 3: 상태 동기화/드래프트 저장 개선
  - URL 상태 동기화 effect 정리
  - draft 저장 빈도/조건 조정
  - 완료 기준: 불필요한 저장/동기화 감소
- Step 4: 캐시/쿼리 유틸 개선
  - `threadCache` 갱신 규칙 점검 및 안전성 보강
  - 필터 쿼리스트링 조합 유틸 정리
  - 완료 기준: 캐시/필터 로직의 단일 진입점 마련
- Step 5: UI 토큰/테마/국제화 정리
  - 토큰 사용 범위 일관화
  - 테마 대비 기준/검증 포인트 추가
  - i18n 설정과 settings store 동기화 정책 정리
  - 완료 기준: UI/국제화 정책 문서화 및 코드 반영

## 리스크 및 대응
- 변경 범위가 넓어 회귀 위험
  - 대응: 단계별로 변경하고, 기능 단위로 확인
- UX/성능 변화가 발생할 수 있음
  - 대응: 주요 흐름(홈/상세/설정/아카이브) 중심으로 수동 확인

## 검증 계획
- `npm run typecheck` / `npm run lint` 우선 수행
- 주요 화면 수동 확인: 홈/스레드 상세/설정/아카이브
- 에러 처리 시나리오 최소 점검(인증 실패/뮤테이션 실패)
